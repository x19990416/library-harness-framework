# Library Harness Framework

面向图书馆业务的 AI Agent 与工作流编排框架，计划在 DeepSeek Harness 提供的运行时、工具调用与 Agent 基础能力之上，沉淀可复用的图书馆领域模型、连接器、分析组件、生成能力和治理规则。

> **项目状态：概念验证（PoC）**  
> 当前仓库主要用于明确架构边界、接口约定与验证路线，尚未提供可用于生产环境的完整实现，也不代表已完成与 DeepSeek Harness 的稳定集成。

## 为什么建立这个项目

图书馆 AI 应用通常需要重复处理数据标准化、领域知识、借阅行为分析、内容生成、事实校验与业务治理。Library Harness Framework 的目标是把这些共性能力从单一业务应用中提取出来，使阅读账单、个性化推荐、智能编目等应用能够共享一致的基础设施，同时保留各自的业务规则。

## 与 DeepSeek Harness 的关系

```text
DeepSeek Harness
  模型调用 / Agent 运行 / 工具执行 / 上下文管理
                    │
                    ▼
Library Harness Framework
  图书馆领域模型 / 连接器 / 分析 / 生成 / 校验 / 工作流适配
                    │
                    ▼
业务应用（首个验证应用：library-reading-bill）
```

- DeepSeek Harness 被视为上游运行底座，原则上通过适配与扩展接入，不在本项目中复制或修改其核心实现。
- 本项目负责图书馆领域能力和稳定的业务扩展边界。
- 上游版本、正式接入方式与兼容范围仍需在 PoC 阶段验证；在验证完成前，不承诺具体 API 或运行时兼容性。

## 模块边界

| 模块 | 计划职责 | 不负责 |
| --- | --- | --- |
| `core` | 领域基础类型、组件契约、注册与配置约定 | 具体业务流程 |
| `data` | 图书馆数据连接与标准化接口 | 特定厂商系统的私有部署配置 |
| `knowledge` | 书目、分类与领域知识访问约定 | 未经来源支持的知识补全 |
| `analysis` | 可复用的借阅与阅读行为分析能力 | 阅读账单专属指标和文案规则 |
| `generation` | 模型调用适配、提示模板契约与结构化输出 | 固定某一家模型或具体应用文风 |
| `validation` | 事实证据关联、质量检查与业务治理接口 | 代替人工审核或合规决策 |
| `workflow` | 工作流定义、执行状态与 Harness 适配 | 强制所有流程使用自主 Agent |

目录中的模块目前仅包含边界说明，不应被视为已实现能力。

## 首个验证应用：library-reading-bill

`library-reading-bill`（市民数字阅读账单）将作为首个应用验证以下流程：

```text
借阅事件标准化
  → 客观事实与语义事实生成/合并
  → 阅读偏好聚类与预测
  → 个性化点评生成
  → 事实、格式与业务规则校验
```

阅读账单的字数、文风、指标口径和对接方式属于应用层；能够被多个应用复用的数据模型、分析契约、生成接口与校验机制才进入本框架。业务应用计划独立演进，本仓库的 `examples/library-reading-bill/` 仅保留集成示例与契约验证材料。

## 渐进式路线图

1. **边界验证**：明确 DeepSeek Harness 接入点、领域数据模型、工具契约和最小治理要求。
2. **阅读账单 PoC**：用真实但脱敏的样例贯通事件、事实、偏好、生成和校验流程。
3. **可复用性验证**：引入第二个应用场景，识别并移除阅读账单特有耦合。
4. **工程化**：补齐测试、可观测性、版本策略、安全基线与兼容性矩阵。
5. **稳定发布**：在接口、许可证和生产验证完成后发布首个可用版本。

更详细的里程碑见 [`docs/roadmap.md`](docs/roadmap.md)。

## 当前不包含

- 已完成的 DeepSeek Harness SDK 封装或插件。
- 可直接部署的生产服务。
- 对任一图书馆业务系统的开箱即用连接器。
- 对生成内容正确性、合规性或业务效果的保证。
