# 架构边界

## 分层

```text
业务应用
  library-reading-bill / future applications
           │
           ▼
Library Harness Framework
  core / data / knowledge / analysis / generation / validation / workflow
           │
           ▼
DeepSeek Harness 适配层
  模型、工具、Agent、上下文和执行能力（待 PoC 验证）
```

## 设计原则

1. **应用与框架分离**：业务口径和展示规则留在应用层。
2. **契约先行**：在实现前明确输入、输出、错误、证据和版本语义。
3. **可追溯**：生成结论应尽量关联来源数据与处理步骤。
4. **确定性优先**：统计、规则与校验优先使用可测试的确定性实现；模型用于适合语义处理的环节。
5. **人工可介入**：高风险或低置信度结果应允许审核、拒绝或重试。
6. **上游隔离**：通过适配层降低对 DeepSeek Harness 特定 API 的直接耦合。

## 数据流（目标形态）

```text
原始业务数据
  → 标准化事件
  → 可验证事实
  → 领域分析结果
  → 结构化生成请求
  → 候选内容
  → 质量与事实校验
  → 应用输出
```

## 尚待验证

- DeepSeek Harness 的正式扩展接口与版本兼容策略。
- 工作流、Agent 与确定性任务之间的职责划分。
- 工具注册、上下文隔离、重试与幂等机制。
- 证据模型、隐私策略和审计日志的最小字段。
- 技术栈、包管理与发布形式。
